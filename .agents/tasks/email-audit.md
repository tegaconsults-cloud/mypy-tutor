# Email Automation Audit — MyPy Tutor

**File audited:** `app/services/email_service.py`
**Audit date:** 2025-07
**Auditor:** Kiro (read-only investigation)

---

## Summary

The email service is **mostly correct** — the domain helpers (`_app_url` / `_frontend_url`) are used with good discipline, and the most sensitive routes (`/auth/confirm`, `/certificate/{level}`, `/verify/{cert_id}`, `/admin.html`) all point to the correct backend domain. However, **three issues** were found:

1. **`send_certificate_email` — `cert_url` query-string is fragile.** The function encodes `name` into the URL with a manual `.replace(" ", "%20")` that does not handle any other special characters (apostrophes, hyphens, accented letters). A learner named "O'Brien" or "Adé Oke" will get a broken certificate link. This is a correctness/robustness bug, not a wrong-domain bug.

2. **`send_payment_receipt_email` — "Go to Your Courses" CTA is fine** (`_frontend_url() + "/?panel=courses"`). The backend `/payment` route itself redirects to `FRONTEND_URL/payment`, so users always land on the frontend. No fix needed here.

3. **`send_admin_notification` — Admin dashboard link is correct** (`_app_url() + "/admin.html"`). The backend does serve `/admin.html` as a static HTML route (`GET /admin.html`). No fix needed.

No email function sends a user to the wrong domain for a route that exists only on the other domain.

## Detailed findings

### ✅ CORRECT — `send_verification_email` (Function 2)

```python
app         = _app_url()
confirm_url = app + "/auth/confirm?token=" + token
```

`/auth/confirm` is handled by `GET /auth/confirm` in `main.py` (line 1246). Uses `_app_url()` (backend). **Correct.**

---

### ⚠️ NEEDS FIX — `send_certificate_email` — `cert_url` encoding (Function 5a)

```python
cert_url = (api + "/certificate/" + cert_level
            + "?name=" + name.replace(" ", "%20")
            + "&learner_id=" + _lid
            + "&admin_view=false")
```

The domain (`_app_url()`) is correct — `/certificate/{level}` is a backend route confirmed at line 1561 of `main.py`. The bug is that `name.replace(" ", "%20")` only handles spaces. A learner name such as `O'Brien`, `Adé`, or `Ng & Sons` will produce a malformed URL because `'`, non-ASCII characters, and `&` are not encoded.

**Recommended fix:**
```python
from urllib.parse import quote as _urlquote

cert_url = (api + "/certificate/" + cert_level
            + "?name=" + _urlquote(name, safe="")
            + "&learner_id=" + _urlquote(_lid, safe="")
            + "&admin_view=false")
```

## Conclusion & Recommendations

### One fix required

| Location | Issue | Fix |
|----------|-------|-----|
| `send_certificate_email`, `cert_url` construction | `name.replace(" ", "%20")` does not properly URL-encode the name parameter | Replace with `urllib.parse.quote(name, safe="")` and also encode `learner_id` with `urllib.parse.quote(_lid, safe="")` |

### Everything else is correct

- All 20+ email functions use `_frontend_url()` for SPA panel links (`/?panel=…`) — correct.
- All backend-route links (`/auth/confirm`, `/certificate/…`, `/verify/…`, `/admin.html`) use `_app_url()` — correct.
- The `_shell()` footer and logo use the correct helpers.
- Caller-supplied URLs (`reset_url`, `confirm_url`, `platform_url`) are the calling code's responsibility.
- The `/payment`, `/voice`, `/terms`, `/privacy` routes on the backend correctly redirect to the frontend (confirmed in `main.py`), so any in-email link to `_frontend_url() + "/payment"` would also be correct — but no email currently links to those paths directly.

### Minor (non-link) observations

- `send_enquiry_email` does not include an unsubscribe link in the admin copy. This is intentional (internal email), not a bug.
- `send_task_assigned_email` passes `platform_url` as a parameter — the caller in `main.py` around line 4790 sets this to `frontend_url.rstrip("/") + "/admin.html"`. Since `/admin.html` is served by the backend, not the frontend, this link in team-member invite emails points to the wrong domain. **This bug is in `main.py`, not in `email_service.py`.** It falls outside the scope of this audit but should be fixed: `admin_url` should use `APP_URL + "/admin.html"`, not `FRONTEND_URL + "/admin.html"`.
